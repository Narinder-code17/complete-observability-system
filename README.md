# Complete Observability System

A containerized end-to-end observability system for monitoring a Flask application using **Prometheus, Grafana, Loki, Promtail, and Jaeger**.

The project demonstrates the three major pillars of observability:

- **Metrics** using Prometheus
- **Logs** using Loki and Promtail
- **Traces** using Jaeger

Grafana provides a centralized interface for visualizing and analyzing the collected observability data.

---

## 1. Project Overview

The system monitors a Flask application and collects application metrics, logs, and traces.

The complete stack runs using Docker Compose.

### Architecture

    Flask Application
          |
          +------------------+
          |                  |
          v                  v
     Prometheus          Promtail
       Metrics              Logs
          |                  |
          |                  v
          |                Loki
          |                  |
          +--------+---------+
                   |
                   v
                Grafana

     Flask Application
          |
          v
        Jaeger
        Traces

Grafana is used as the main visualization layer for metrics and logs, while Jaeger provides distributed tracing.

## 5. Docker Compose Services

The project contains six main services.

### Flask Application

The Flask application provides the application endpoints and exposes Prometheus-compatible metrics.

Port:

    5000

Endpoints:

    GET /
    GET /health
    GET /api/data
    GET /api/error
    GET /metrics

The `/api/error` endpoint is used to intentionally generate an HTTP 500 error for testing error monitoring.

---

### Prometheus

Prometheus collects metrics exposed by the Flask application.

Port:

    9090

The application exposes the following metric:

    app_http_requests_total

Example PromQL query:

    app_http_requests_total

Example rate query:

    rate(app_http_requests_total[5m])

This calculates the HTTP request rate over the previous five minutes.

---

### Loki

Loki is responsible for centralized log storage.

Port:

    3100

Application logs are collected by Promtail and sent to Loki.

Example LogQL query:

    {service_name="observability-app"}

This query displays logs generated by the Flask application.

---

### Promtail

Promtail collects Docker container logs and forwards them to Loki.

Promtail reads Docker container log files and attaches useful labels.

Example labels include:

    container
    filename
    job
    service_name
    stream

The application can be filtered using:

    {service_name="observability-app"}

---

### Grafana

Grafana provides the visualization interface.

Port:

    3001

Grafana is connected to:

    Prometheus
    Loki
    Jaeger

Grafana is used to visualize HTTP metrics and search application logs.

---

### Jaeger

Jaeger provides distributed tracing capabilities.

Jaeger UI:

    http://localhost:16686

OTLP ports:

    4317
    4318

    {endpoint="/", instance="app:5000", job="observability-app", method="GET", status="200"}

## 19. Troubleshooting

### Grafana Does Not Open

Check the service:

    docker compose ps

Restart Grafana:

    docker compose restart grafana

Then open:

    http://localhost:3001

---

### Loki Shows No Logs

Check Promtail:

    docker compose logs promtail

Check Loki:

    docker compose logs loki

Then open Grafana Explore and run:

    {service_name="observability-app"}

Also verify that the selected Grafana time range includes the period when the logs were generated.

---

### Prometheus Shows No Metrics

Open:

    http://localhost:5000/metrics

Verify that metrics are being exposed.

Then open:

    http://localhost:9090

Query:

    app_http_requests_total

Check Prometheus logs if necessary:

    docker compose logs prometheus

---

### Application Is Not Responding

Check:

    docker compose ps

Then check:

    docker compose logs app

Restart the application:

    docker compose restart app

---

### Rebuild After Code Changes

If application code or Docker configuration is modified:

    docker compose up -d --build

## 26. Project Summary

The Complete Observability System demonstrates an end-to-end monitoring architecture for a containerized Flask application.

The Flask application generates metrics, logs, and tracing information. Prometheus collects metrics, Promtail forwards container logs to Loki, and Jaeger provides distributed tracing capabilities. Grafana provides a centralized interface for visualizing and analyzing the observability data.

The project successfully demonstrates the integration of:

    Metrics  → Prometheus
    Logs    → Promtail → Loki
    Traces  → Jaeger
    Visuals → Grafana

The final system provides a practical example of how modern DevOps teams can monitor application health, investigate errors, analyze request activity, and troubleshoot services using a unified observability stack.
